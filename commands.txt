Experiment 4: Jenkins Installation & Build Job (CI)
Installation on Ubuntu/WSL
Bash
sudo apt update && sudo apt install fontconfig openjdk-17-jre -y
sudo wget -O /usr/share/keyrings/jenkins-keyring.asc https://pkg.jenkins.io/debian-stable/jenkins.io-2023.key
echo deb [signed-by=/usr/share/keyrings/jenkins-keyring.asc] https://pkg.jenkins.io/debian-stable binary/ | sudo tee /etc/apt/sources.list.d/jenkins.list > /dev/null
sudo apt update && sudo apt install jenkins -y
sudo systemctl start jenkins
sudo systemctl enable jenkins
Get Initial Admin Password
Bash
sudo cat /var/lib/jenkins/secrets/initialAdminPassword
Access UI: Open http://localhost:8080 in your web browser.

Experiment 5: Jenkins Master-Slave Architecture
Procedure Summary:

Go to Jenkins Dashboard → Manage Jenkins → Nodes → New Node.

Define the node name, select Permanent Agent, and configure the remote root directory.

Set launch method to Launch agent via connecting to the controller (or via SSH).

Run the provided Java command or agent connection script on the target slave machine to link it back to the master.

Experiment 9: Puppet Installation & Configuration (Pull-Based)
Installation (Ubuntu/WSL)
Bash
sudo apt update && sudo apt upgrade -y[cite: 19]
sudo apt install puppet -y
puppet --version[cite: 20]
Applying a Standalone Manifest (site.pp)
Bash
mkdir -p ~/puppet-lab && cd ~/puppet-lab
nano site.pp
(Sample code for Apache provisioning)[cite: 20]:

Puppet
package { 'apache2':
  ensure => installed,
}
file { '/var/www/html/index.html':
  ensure  => file,
  content => 'Hello World! Configured using Puppet.',
}
service { 'apache2':
  ensure  => running,
  enable  => true,
  require => Package['apache2'],
}
Execute & Verify
Bash
sudo puppet apply site.pp[cite: 21]
sudo systemctl status apache2[cite: 21]

(Code snippet inside init.pp):

Run module test:

Bash
nano module_test.pp  # contents: include mymodule
sudo puppet apply --modulepath=. module_test.pp

Bash

Puppet

Run class manifest:

Bash
